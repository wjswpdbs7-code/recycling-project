## 1. 프로젝트 개요

### 1.1 목표
가정에서 발생하는 재활용 쓰레기를 투입구에 넣으면 **비전 AI가 품목을 인식하고, 기구부가 해당 수거함으로 자동 분배**하는 탁상~스탠드형 시제품을 제작한다.

### 1.2 핵심 가치
- 분리배출 오류율 감소 (특히 투명 페트 별도 배출 등 헷갈리는 규정 자동 처리)
- 배출 통계 대시보드 제공 (품목별 배출량, 재활용 기여도)
- AI(비전 분류) + 임베디드 제어 + 웹 대시보드를 아우르는 풀스택 포트폴리오

### 1.3 성공 기준 (시연 기준)
| 항목 | 목표치 |
|---|---|
| 분류 정확도 (시연 품목) | ≥ 90% |
| 1개 처리 시간 (투입→수거함 도달) | ≤ 8초 |
| 연속 처리 | 10개 연속 무고장 |
| 대시보드 | 실시간 분류 이력·통계 표시 |

## 2. 분류 품목 (v0.2 확정 — 학습 17종 / 시연 분배 4+1)

초기안(6종+예외)은 검토 결과 폐기하고, **"학습은 세밀하게(17종), 분배는 기구에 맞게(4품목+판별불가)"** 2계층 구조로 확정했다. 근거와 매핑 상세는 [02_클래스_설계.md](02_클래스_설계.md).

**시연 기기 분배 (수거함 5칸):**

| 수거함 | 대상 | 보조 검증 |
|---|---|---|
| 투명 페트 | 무색 투명 생수·음료병 (라벨·뚜껑 부착 포함) | 로드셀(가벼움) |
| 일반 플라스틱 | 유색 페트, PP/PE 용기 | |
| 캔 | 알루미늄·철 캔 | 유도형 금속센서 |
| 유리 | 유리병 (전 색상) | 로드셀(무거움) |
| 판별불가 | 오염 8종·비대상 품목(종이·비닐 등)·저신뢰·복수투입 | 품목명 안내(배출 코칭) 표시 |

**학습 클래스 (17종, 아파트 규정 풀스펙):** 클린 9종(4품목 + 종이·종이팩·비닐·스티로폼·건전지) + 품목별 오염 8종. 아파트형(수거함 9~10칸) 확장 시 재학습 없이 병합 규칙만 변경.

> **설계 원칙(유지):** 신뢰도(confidence)가 임계값 미만이면 억지로 분류하지 않고 "판별불가" 칸으로 보낸다. 시연 중 오분류로 인한 신뢰 하락을 막는 안전장치이자, 실제 제품에서도 합리적인 UX. 비닐·종이를 "분배"하지 않는 이유는 기구 걸림·투입구 규격 문제이며, "인식"은 17종 학습으로 수행해 안내 메시지에 활용한다.

## 3. 시스템 아키텍처

```
[투입구+도어]                                      [웹 대시보드]
     │                                                  ▲
     ▼                                                  │ (Supabase Realtime)
[촬영 스테이지] ──이미지──▶ [AI 추론부] ──클래스──▶ [제어부(MCU)]
 (조명 박스,               (YOLO/CNN)       │        │
  IR 투입감지,                              │        ▼
  로드셀·금속센서*)                          │   [분배 기구부]
                                            │    회전 캐러셀 + 배출 도어
                                            ▼        │
                                      [DB: 분류 이력] ▼
                                              [수거함 ×6 + 판별불가함]
```

### 3.1 처리 흐름 (상태 머신)
1. **IDLE** — 대기. IR 센서가 투입 감지하면 →
2. **CAPTURE** — 도어 잠금, 조명 ON, 카메라 촬영 (2~3장, 각도/노출 다르게)
3. **INFER** — AI 추론. (보조: 금속센서로 캔 여부 교차검증, 로드셀로 무게 기록)
4. **SORT** — 캐러셀을 해당 수거함 위치로 회전 → 바닥 도어 개방 → 낙하
5. **LOG** — 결과를 로컬 DB + Supabase에 기록, 대시보드 실시간 갱신
6. **RESET** — 원위치 복귀 → IDLE. 오류 시 **ERROR** 상태(부저+LED, 대시보드 알림)

### 3.2 분배 기구 방식 선정

6분류는 플리퍼(차단판) 방식으로는 기구가 5개 이상 필요해 복잡도가 폭증한다. **회전 캐러셀 방식을 채택**한다.

| 방식 | 구조 | 6분류 적합성 | 판정 |
|---|---|---|---|
| **회전 캐러셀 (채택)** | 촬영 스테이지 바닥이 열리고, 그 아래 수거함 6+1개가 원형 배치된 턴테이블이 회전해 정렬 | 모터 1개(스텝모터)로 N분류 확장 가능. 기구 최단순 | ✅ |
| 회전 슈트 | 낙하 슈트가 회전해 고정 수거함으로 유도 | 가능하나 슈트 길이만큼 높이 증가, 비닐·종이가 슈트에 걸림 | △ |
| 컨베이어 + 플리퍼 | 벨트 위 이송 중 클래스별 차단판이 쳐냄 | 산업 표준이나 6분류엔 플리퍼 5개+벨트 → 비용·고장점 최다 | ✖ |

**캐러셀 상세:**
- 스텝모터(NEMA17) + 감속(GT2 벨트 or 3D프린팅 기어) → 턴테이블 회전
- 원점 검출: 홀센서 or 리미트 스위치 1개 (전원 인가 시 호밍)
- 촬영 스테이지 바닥: 서보(MG996R) 2개로 여닫는 양문형 트랩도어
- 유리 파손 방지: 낙하 높이 ≤ 15cm + 수거함 바닥 EVA 폼

## 4. AI 설계

### 4.1 모델 (v0.2 확정: YOLO11n)
- **확정: YOLO11n (detection)** — 물체 위치+클래스 동시 획득 + **복수 투입 감지(박스 수)·빈 스테이지 확인**이 필수 기능이라 classification 단독으로는 불가.
  Run A 실증: 공식 검증셋 mAP50 0.985 ([03_학습_보고서.md](03_학습_보고서.md)) — n(nano)으로 충분함 확인
- 승급 게이트: 클린 mAP50 < 0.95 또는 페트↔유리 혼동 발생 시에만 YOLO11s 비교 실험
- (기각된 대안 기록) MobileNet류 classification — 물체 1개 보장을 모델이 검증할 수 없어 기각. crop+classification 2단계는 fine-tuning 후에도 페트↔유리가 안 잡힐 때의 예비 카드로만 유지
- 학습: 전이학습(COCO pretrained) → 커스텀 데이터셋 fine-tuning
- 배포: ONNX/TensorRT 변환, 엣지에서 추론 (저가형: NCNN/ONNX Runtime CPU, 표준형: TensorRT GPU)

### 4.2 데이터셋 (v0.2 확정)
| 소스 | 내용 | 용도 |
|---|---|---|
| **AI Hub 생활폐기물(71385) 실내형분류기** | Training 102,271장 + 공식 Validation 12,784장. 밀폐 박스·상부 카메라 — 우리 스테이지와 동일 구도. 29종 코드→17클래스 매핑 | **주력 학습 (진행 중)** |
| **자체 촬영 (핵심)** | 실제 촬영 스테이지·조명 환경에서 품목별 300~500장 (dirty·other 포함) | fine-tuning 주력. 도메인 갭 제거 |
| (기각) TACO / TrashNet 등 해외 데이터 | 길거리·일상 사진 — 도메인 불일치, 투명페트 구분 없음 | 사용 안 함 |

주: AI Hub는 해외 IP 다운로드 차단 → 국내 회선으로 받아 GPU 서버에 업로드하는 파이프라인 확립 (상세: 02 문서 8장 운영 노트)

- 자체 촬영은 **실기기 조명 박스 안에서** 찍는 것이 정확도에 결정적 (배경·조명 고정 → 문제 난이도 급감)
- 증강: 회전, 밝기, 블러, 배경 노이즈. 클래스당 실효 2,000장 목표
- 학습 인프라: RunPod GPU (기존 ABC 프로젝트 파이프라인 재사용 가능)

### 4.3 난이도 대응 (v0.2 갱신)
- **비닐·종이**: 분배 대상에서 제외(기구 걸림·규격 문제). 인식은 17클래스 학습으로 수행하고 "판별불가함 + 품목 안내"로 처리 — 난이도 문제를 UX로 우회
- **투명 페트 vs 유리**: 시각적 유사 → 로드셀 무게를 보조 특징으로 (유리 평균 무게 ≫ 페트). 규칙 기반 후처리: `투명용기 && 무게 > 150g → 유리 가중`. Run A 실측에서는 혼동 미미 (both mAP50 0.99+)
- **캔**: 유도형 근접센서(금속 감지)로 교차검증 → 캔 오분류 사실상 제거
- **오염 판별(신규)**: 품목별 오염 8종을 별도 클래스로 학습 → "세척 후 배출" 안내. dirty 판정은 정밀도 우선(임계값 상향)으로 클린을 오염으로 보내는 오류 최소화

## 5. 하드웨어 설계 — 예산 티어별

### 5.1 저가형 (목표 ~35만원, 4–6주)

**컨셉:** 라즈베리파이 단일 보드로 추론+제어 통합. 프레임은 MDF/3D프린팅.

| 부품 | 사양 | 예상가 |
|---|---|---|
| 라즈베리파이 5 (8GB) | 추론+제어+서버 통합 | 110,000 |
| 카메라 | Pi Camera Module 3 or USB 웹캠(오토포커스) | 35,000 |
| 스텝모터+드라이버 | NEMA17 + A4988/TMC2208 | 20,000 |
| 서보 ×2 | MG996R (트랩도어) | 12,000 |
| 센서류 | IR 투입감지, 홀센서(원점), 유도형 금속센서 | 20,000 |
| 로드셀+HX711 | 5kg | 8,000 |
| 조명 | LED 바 + 디퓨저 (유백 아크릴) | 15,000 |
| 전원 | 12V 5A SMPS + 5V 변환(강압) | 20,000 |
| 프레임·외장 | MDF 레이저컷 or 3D프린팅 + 아크릴 | 60,000 |
| 수거함 7개 | 시판 소형 수납함 | 20,000 |

- 추론 속도: YOLOv8n 640px, Pi 5 CPU(NCNN) 기준 약 3~5 FPS → 정지 촬영 1장 추론에 충분

| 스텝모터+드라이버 | NEMA17 ×1~2 + TMC2209 (정숙) | 35,000 |
| 서보 ×2~4 | 메탈기어 디지털 서보 | 30,000 |
| 센서류 | IR, 홀센서, 유도형 금속센서, 도어 리미트 | 35,000 |
| 로드셀+HX711 | | 8,000 |
| 조명 | 링라이트 + 디퓨저 박스 (촬영 품질 ↑) | 40,000 |
| 전원 | 12V 10A SMPS + DC-DC 분배 | 35,000 |
| 프레임 | 2020 알루미늄 프로파일 + 아크릴 패널 | 150,000 |
| 수거함 + 턴테이블 기구 | 베어링(회전판용 터닝테이블 베어링), 제작비 | 80,000 |
| 터치 디스플레이 (선택) | 7" — 기기 전면 UI | 60,000 |
| 기타·예비 | | 50,000 |
| **합계** | | **약 1,000,000** |

- 역할 분리: **Jetson = 추론+서버+대시보드 백엔드**, **ESP32 = 상태머신 실시간 제어**. 시리얼 프로토콜(JSON 라인)로 통신 → 한쪽 재시작해도 안전
- 추론: TensorRT FP16으로 YOLO11n 30+ FPS → 실시간 프리뷰·복수 투입 감지 가능
- 확장: 터치 UI로 "이거 맞아요?" 사용자 피드백 → 재라벨링 데이터 수집 루프 (액티브 러닝 스토리)

### 5.3 공통 기구 치수 (초안)
- 전체: 약 W450 × D450 × H900 mm (스탠드형)
- 상단 1/3: 투입구+촬영 스테이지 (내부 300×300×250, 무광 백색 배경)

## 6. 소프트웨어 설계

### 6.1 스택
| 계층 | 기술 | 비고 |
|---|---|---|
| AI 학습 | Python, PyTorch, Ultralytics, RunPod GPU | 기존 파이프라인 재사용 |
| 엣지 추론 | ONNX Runtime(저가형) / TensorRT(표준형) | |
| 기기 서비스 | Python (FastAPI + asyncio 상태머신) | 카메라·추론·제어 오케스트레이션 |
| MCU 펌웨어 (표준형) | Arduino C++ (ESP32) — 시리얼 JSON 프로토콜 | |
| DB / 실시간 | SQLite(로컬 큐) → Supabase 동기화 | 오프라인 내성: 로컬 선기록 후 업로드 |
| 대시보드 | Next.js or Streamlit + Supabase Realtime | 분류 이력, 품목별 통계, 오분류 신고 |

### 6.2 시리얼 프로토콜 (표준형, Jetson↔ESP32)
```
Jetson → ESP32 : {"cmd":"sort","slot":3}        // 3번 수거함으로
ESP32 → Jetson : {"evt":"inserted"}             // 투입 감지
ESP32 → Jetson : {"evt":"done","slot":3,"ms":4200}
ESP32 → Jetson : {"evt":"error","code":"HOMING_FAIL"}
```

### 6.3 대시보드 핵심 화면
1. 실시간 피드: 방금 분류된 품목 사진 + 클래스 + 신뢰도
2. 통계: 일/주별 품목 배출량, 재활용률, 판별불가 비율
3. 오분류 신고: 사용자가 정정 → 재학습 데이터로 축적

## 7. 개발 일정 (표준형 12주 기준 / 저가형은 1–5주차 압축)

| 주차 | 마일스톤 |
|---|---|
| 1–2 | 상세 설계 확정, 부품 발주, 데이터셋 수집 시작 (AI Hub + 자체) |
| 3–4 | AI 1차 학습 (공개 데이터) → 베이스라인 정확도 측정. 캐러셀 기구 프로토타입 |
| 5–6 | 프레임·기구 조립, MCU 펌웨어(상태머신·호밍·트랩도어) |
| 7–8 | 실기기 촬영 데이터 수집 → fine-tuning → 엣지 배포. HW-SW 통합 |
| 9–10 | 대시보드, Supabase 연동, 오프라인 큐. 연속 처리 테스트 |
| 11 | 신뢰도 임계값·보조센서 융합 튜닝, 오류 처리(걸림·중복투입) |
| 12 | 시연 리허설, 발표자료, 문서화 |

## 8. 리스크와 대응

| 리스크 | 확률 | 대응 |
|---|---|---|
| 비닐·종이 인식률 저조 | 높음 | 자체 데이터 최다 확보, 조명 고정, 최악 시 시연 품목 큐레이션 + "판별불가" UX로 방어 |
| 기구 걸림 (비닐이 트랩도어에 붙음) | 중간 | 도어 개방각 크게, 스테이지 바닥 경사, 정전기 방지 처리 |
| 부품 배송 지연 | 중간 | 1–2주차 조기 발주, 핵심 부품(보드·모터)은 국내 재고 우선 |
| 저가형 추론 속도 부족 | 낮음 | 정지 촬영 1장 방식이라 3초 이내면 충분. 입력 해상도 480px로 축소 가능 |
| 유리 파손 | 낮음 | 낙하고 15cm 제한 + 완충재. 시연은 플라스틱 재질 유리모형도 예비 |
